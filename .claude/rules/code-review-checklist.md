# STM32 C 代码安全审查检查列表

## 内存安全

### 缓冲区溢出
- [ ] 所有数组访问都有边界检查
- [ ] `strcpy()` 已替换为 `strncpy()`
- [ ] `sprintf()` 已替换为 `snprintf()`
- [ ] DMA 缓冲区大小与声明大小匹配
- [ ] 指针计算无越界可能

### 栈溢出
- [ ] 本地数组大小合理（< 512 字节为佳）
- [ ] 递归深度有限制
- [ ] 中断处理函数栈使用量最小
- [ ] 全局变量用于大数据块（DMA、缓冲）

### 内存泄漏
- [ ] 不使用 `malloc()` 或已审计其使用
- [ ] 所有分配的资源都有对应释放
- [ ] 中断中未调用 `malloc()`/`free()`

## 中断安全

### ISR 规则遵循
- [ ] ISR 中无阻塞操作（无 `HAL_Delay()`, `HAL_UART_Transmit()` 等）
- [ ] ISR 中无浮点运算（除非 FPU 已配置且中断级别允许）
- [ ] 中断共享变量使用 `volatile` 修饰
- [ ] ISR 代码简短快速（< 几微秒）
- [ ] 中断优先级合理设置（避免优先级倒置）

### 原子性
- [ ] 多字节变量访问使用原子操作或关中断保护
- [ ] 标志变量为 8 位整数或 `volatile uint8_t`
- [ ] 临界区用 `HAL_NVIC_DisableIRQ()`/`EnableIRQ()` 保护

## HAL 库使用

### 返回值检查
- [ ] 每个 `HAL_*` 函数调用检查返回值
- [ ] `HAL_OK` 是预期返回值
- [ ] 错误情况调用 `Error_Handler()`
- [ ] 超时返回值 `HAL_TIMEOUT` 被处理

### 初始化顺序
- [ ] `SystemClock_Config()` 首先调用
- [ ] `MX_GPIO_Init()` 在其他外设前
- [ ] 中断启用在所有初始化后
- [ ] 无重复初始化同一外设

### CubeMX 生成代码
- [ ] USER CODE 标记间的代码不会被覆盖
- [ ] 自定义模块在单独文件中，非生成文件
- [ ] 生成文件中无手动修改

## 外设使用

### 通信外设 (UART/SPI/I2C)
- [ ] DMA 缓冲是全局/静态，非栈分配
- [ ] DMA 操作前禁用中断或确保原子性
- [ ] 总线速率和延迟配置正确
- [ ] 错误处理覆盖超时和接收错误

### GPIO
- [ ] 引脚配置与硬件原理图匹配
- [ ] 输出高电平前检查上拉/下拉设置
- [ ] 无冲突的复用功能分配

### 定时器
- [ ] 预分频和自动重加载计数正确
- [ ] 中断频率合理（不过高避免 CPU 饱和）
- [ ] PWM 周期与占空比配置验证

## 代码结构

### 命名规范
- [ ] 全局变量前缀 `g_`
- [ ] 静态变量前缀 `s_`
- [ ] 函数名清晰表达功能
- [ ] 宏定义全大写带前缀

### 模块化
- [ ] 每个外设一个独立 `.c`/`.h` 对
- [ ] 头文件有 include 保护: `#ifndef MODULE_H`
- [ ] 函数声明在头文件，定义在 `.c`
- [ ] 无循环依赖

### 文件位置
- [ ] 生成的代码在 `Core/Src/Drivers/`
- [ ] 用户代码在 `Core/Src/` 新文件中
- [ ] 不修改 `Core/Src/main.c` 外的生成文件

## 数据类型

### 整数类型
- [ ] 使用定宽类型：`uint8_t`, `uint16_t`, `uint32_t` 等
- [ ] 避免 `int`/`long` 不确定大小的类型
- [ ] 有符号/无符号匹配操作预期

### 浮点
- [ ] 浮点仅用必要地方（不用于定时器 tick）
- [ ] F407 有 FPU，但避免频繁转换
- [ ] 比较浮点用 epsilon 容差

## 调试与日志

### 日志输出
- [ ] 未发布的代码中可保留 `printf()` 调试
- [ ] 严格避免在关键中断内输出日志
- [ ] 日志缓冲充足避免覆盖

### 断言
- [ ] 关键假设用 `assert()` 验证
- [ ] 发布版本可禁用 `assert()`（定义 `NDEBUG`）
- [ ] 参数有效性检查

## 发布前检查

### 编译
- [ ] 无编译警告或已审计
- [ ] Release 版本编译通过
- [ ] 没有未使用的变量/函数

### 静态分析
- [ ] 运行 clang-analyzer 或类似工具
- [ ] 未初始化指针已修复
- [ ] 潜在的空指针访问已检查

### 功能测试
- [ ] 正常路径测试
- [ ] 错误/异常条件测试
- [ ] 边界情况测试（最大/最小值）
- [ ] 硬件集成测试

## 标记符号

用于代码审查反馈：

| 符号 | 含义 | 示例 |
|------|------|------|
| 🔴 **CRITICAL** | 安全问题，必须修复 | 栈溢出、缓冲区溢出 |
| 🟠 **HIGH** | 功能问题或潜在故障 | 未检查返回值、ISR 中阻塞 |
| 🟡 **MEDIUM** | 代码质量或可维护性 | 魔数应定义为宏 |
| 🟢 **LOW** | 建议改进 | 更清晰的命名 |
| ✅ **APPROVED** | 通过审查 |  |

## 审查流程

1. **自动检查** - 编译警告、静态分析
2. **手动审查** - 针对上述检查列表逐一检查
3. **反馈** - 使用标记符号、具体建议
4. **修复** - 开发者应用修改
5. **复审** - 验证所有问题已解决
